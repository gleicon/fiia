# Project: Fiia

## Overview

Fiia is a configuration-drift and liveness system for fleets, built around a
single binary (`fiia-agent`) and no server side. You provision with Ansible;
`fiia-agent` records a manifest (files / packages / services, plus a snapshot
of installed packages and active services) and periodically checks the node
against it, emitting verdicts and heartbeats over OpenTelemetry to your own
pipeline. All alerting happens downstream (Prometheus / Grafana). No hub, no
secrets, no certificates. Detect by default; remediation is an explicit opt-in
(`-remediate` / `remediate = true`), and file content is always restored by the
provisioning playbook (IaS is the source of truth for content).

## Stack

| Concern | Choice |
|---------|--------|
| Language | Go 1.26, statically compiled, CGO disabled |
| Telemetry | OpenTelemetry OTLP/HTTP (+ stdout) — gauges, counter, per-check log records |
| Manifest | JSON (`schema_version` 1) generated by the agent; the single source of truth for what to check |
| Ansible | `fiia.fleet` collection → `agent` role; invokes `-write-manifest` as last step |
| Observability (E2E) | `e2e/observe`: OTel collector → Prometheus → Grafana (+ alert rules) |
| Config | TOML (`BurntSushi/toml`) |
| **Build** | `go build ./cmd/agent` |
| **Test** | `go test ./...` |

## Constraints

**Safety (non-negotiable):**
- Agent has no write path to its own manifest (read-only check); it never
  rewrites host config. Remediation is opt-in and only touches packages &
  services recorded in the snapshot — never files, and never any state the
  manifest doesn't capture (users, cron, firewall, sysctl, …).
- File content is restored exclusively by the provisioning playbook (IaS).

**Resource (systemd unit on edge nodes):**
- CPU 10%, memory 256M, IO 512K, `Nice=19`, watchdog 120s.

**Architecture:**
- `cmd/agent` imports only `internal/agent/*` and `internal/assert`.
- `audit` never touches OTel; only `otel` imports the SDK.
- No new external dependencies without written justification (git history
  holds the recorded decisions).
- Golden rule: fiia checks only what the manifest documents — packages/services
  are snapshotted automatically, files must be declared in the playbook or the
  manifest.

## Status

Manifest generation, drift checking (files/packages/services/snapshot), OTel
emission, fleet-visible deviation metric (`fiia.drift.details`), permission
alerts (`svc:unverifiable`, `CHECK_ERROR`), opt-in auto-remediation
(`-remediate`/`remediate=true`), four Docker E2E suites, live
Prometheus/Grafana stack. See `docs/` for the running doc set.
